The Procedural Memory Graph

The representation itself. A world-centric, hierarchical graph where every node is a world state — there are no action, recovery, or control nodes. Everything a procedure needs lives inside the states.

Graph Schema

A four-level hierarchy

A Task divides into semantic Milestones; each Milestone owns a Local Execution Graph; the graph is a chain of Procedural States. Every node represents a world state — procedural execution emerges from traversing between them.

Task→ Milestones→ Local Execution Graph→ Procedural States

The Local Execution Graph is a directed graph with cycles, not a DAG — retries and recovery are simply loops back to a previously known state. Nothing in the graph is labelled "recovery"; it is just another valid path.

state ├── World Representation │ ├── Procedural Geometry // relations + contact graph │ ├── Reference Geometry // egocentric object poses │ └── Dense Reconstruction // by reference, via Frame Range ├── Object Instances // → task-level Object Registry ├── Frame Range // canonical temporal reference ├── Action Group // dependency DAG of parameterized actions ├── Observable Conditions // symbolic; verification is external ├── Exit Criteria // boolean expressions → target states ├── Statistics └── Confidence
State Model

A state is a stable phase of the world

A Procedural State is not a single frame — it spans a meaningful segment of time during which the world holds a stable configuration. It is event-driven: a new node is created only on a meaningful procedural event, never because time passed.

World Representation

Three purpose-based geometry layers: Procedural (relations + contacts), Reference (egocentric poses), and Dense Reconstruction (referenced by Frame Range, never embedded). The graph stays a knowledge graph, not a 3D database.

Objects: registry + instances

Identity is global, state is local. A task-level Object Registry holds each physical object once; per-state Object Instances reference it and add only what varies — pose, articulation, contacts.

Egocentric & event-driven

Everything is relative to the doer's viewpoint. Waiting ten seconds doesn't create a node — temporal information attaches to the existing state via its Frame Range.

Action Groups

A dependency DAG of parameterized actions

Each state owns an Action Group — the intentional operations that transform the world. It is a partial-order DAG: edges are dependency edges, not temporal ones. Independent actions run concurrently; dependent actions wait for the conditions their parents produce.

An Action is a rich object

verbactortarget parametersmotion refrole

Parameters are the intended operating point — temperature = 350 °C, knob → Simmer, force = gentle. This is intention, distinct from Motion Reference (how the body moved) and Observable Conditions (the verified outcome). Over many demonstrations the PMG can learn canonical values and their ranges.

Order-invariant compilation

Two demonstrations — Rotate→Pick→Click and Pick→Rotate→Click — compile to the same Action Group, because the graph stores dependencies, not the order that happened to be performed.

Coordination constraints capture genuinely simultaneous cooperation — maintain heat while pulling the pin — which is where timing synchronization between parallel actions lives.

Execution Contract

Symbolic knowledge in the graph — execution outside it

The recurring design principle: the graph stores symbolic procedural knowledge; execution-specific concerns — perception verification, motion generation, controllers, scheduling — stay external contracts that operate over the graph rather than becoming part of it.

in the graph

Observable Conditions

Symbolic, verifiable evidence that the world changed. A predicate (subject · relation · object/value) plus a temporal qualifier.

flame present tip_temp ≥ 350 °C // sustained ≥ 5s pin[i] removed-from PCB

Exit Criteria are boolean expressions over condition ids, each mapped to a next state. Retries, alternatives, and recovery are just loops and branches here.

outside the graph

Verification Contract

How a condition is checked lives outside the graph, keyed by condition id — so the memory stays perception-agnostic.

verify: specular-reflectance detector tolerance: gloss Δ > 0.3 evidence: frames 7010–7090 confidence: 0.86

The PMG Perception Encoder fills these contracts later. The graph says what must be true; the contract says how to confirm it.
